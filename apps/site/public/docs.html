Introduction & Philosophy

As AI coding agents transition from single-prompt assistants into autonomous, long-running loops (such as Claude Code, Cursor, Codex, and custom multi-agent swarms), engineering teams confront a systemic failure mode: working tree collisions.

When multiple agents operate concurrently within a single working directory, they overwrite each other's unstaged files, trigger false build failures, hallucinate conflicting merge resolutions, and burn tokens fighting over Git state. Furthermore, without observability, agent loops incur uncontrolled token expenditure on repetitive context and un-cached tool schemas.

Switchyard solves this by providing a complete, local-first multi-agent operating environment built on three complementary principles:

  • Deterministic Isolation: Agents must execute in separate, isolated Git worktrees backed by atomic filesystem locks.
  • Economic Transparency: Every prompt token, cache hit, and waste artifact must be measured against verified provider price tables.
  • Local Governance: Traffic and credentials must route through a zero-telemetry local gateway that records an immutable audit trail before any code lands in production.
Zero-Model Core Guarantee

Switchyard's orchestration core (@switchyardhq/switchyard) contains zero machine learning models. It does not invoke LLMs to decide branch merges or detect conflicts. All collision detection is mathematically calculated via Git tree intersection diffs. Orchestration remains 100% deterministic, reproducible, and verifiable.

Quickstart Guide

Initialize Switchyard in an existing Git repository and spawn your first isolated agent in less than two minutes:

BASH · QUICKSTART WORKFLOW 
# 1. Install Switchyard and Contextbill globally
npm install -g @switchyardhq/switchyard contextbill

# 2. Inside your target Git repository, initialize the fleet workspace
fleet init

# 3. Start the local Fleet Gateway proxy (running at 127.0.0.1:52425)
fleet gateway --port 52425 &

# 4. Spawn an isolated worktree for an API development agent
fleet spawn worker-api --gateway

# 5. Spawn an isolated worktree for a frontend authentication agent
fleet spawn worker-auth --gateway

# 6. Verify concurrent collision status across all active worktrees
fleet check

# 7. Open the local browser-based fleet review portal
fleet dashboard --once

Pillar 1: Fleet Worktree Engine

Switchyard manages isolated agent working environments using native Git worktrees. When you spawn an agent, Switchyard creates a linked worktree under .fleet/agents/<name> checked out to a dedicated branch (fleet/<name>).

This ensures that each agent operates in full filesystem isolation. Build artifacts, node_modules caches, and temporary files remain quarantined within the agent's worktree.

Index-Tree Collision Detection

Git allows multiple worktrees to modify files independently, but conflicts occur when two agents touch the same file or overlapping line ranges. Switchyard computes collisions prior to merging:

  • Tree Intersection: Switchyard queries the Git index of each agent's branch against HEAD using git diff-tree -r --name-only HEAD <branch>.
  • Conflict Classification: Files modified by only one agent are classified as clean candidates. Files modified by two or more agents are flagged as active collisions with detailed file-level ownership.
  • Dirty Worktree Protection: If an agent has uncommitted changes in its worktree, Switchyard blocks merge operations to prevent lost work.

Pillar 2: Context Economics (Contextbill)

Modern coding agents consume hundreds of thousands of tokens per session. Without visibility into prompt caching and token distribution, engineering teams experience unexpected cost escalations.

Contextbill (contextbill) is a zero-dependency, local-first token observability engine that parses agent transcripts and attributes exact costs down to the individual tool invocation.

60-Day Verified Pricing Model

Pricing data is maintained in a strictly versioned prices.json catalog verified every 60 days against official provider documentation. It covers all major model families:

  • Anthropic: Claude 3.5 Sonnet, Claude 3.5 Haiku, Claude 3 Opus
  • OpenAI: GPT-4o, GPT-4o-mini, o1, o3-mini
  • Google Cloud / Gemini: Gemini 1.5 Pro, Gemini 1.5 Flash, Gemini 2.0 Flash
  • Open Weights & DeepSeek: DeepSeek V3, DeepSeek R1, Llama 3.3

Prompt Caching Mathematics

Contextbill models provider prompt caching structures with precision. For modern architectures (such as Anthropic prompt caching), the effective cost formula is calculated as:

Cost Formulation

Total Cost = (Input Tokens × Base Input Rate) + (Output Tokens × Output Rate) + (Cache Read Tokens × 0.10 × Base Input Rate) + (Cache Write Tokens × 1.25 × Base Input Rate)

Contextbill differentiates between 5-minute ephemeral cache TTLs (standard conversation continuity) and 1-hour persistent caching, alerting developers when an agent's pause duration causes cache evictions.

Context Bloat & Waste Diagnostics

When scanning session logs, Contextbill flags three critical waste patterns:

  1. Tool Schema Duplication: Identical MCP tool definition payloads re-transmitted on consecutive turns without prompt cache activation.
  2. System Prompt Drift: Unmodified system directives sent with non-deterministic variable injection (e.g. dynamic millisecond timestamps) that bust the prompt cache.
  3. Dead Chunk Accumulation: Reading entire 2,000-line source files repeatedly instead of targeted line-range reads.
BASH · SCANNING AGENT TRANSCRIPTS 
# Scan current directory for agent session logs and generate cost report
contextbill scan . --format summary

# Output detailed token breakdown with cache multipliers as JSON
contextbill scan ~/.claude/projects/my-repo --format json > report.json

# Check current active pricing table for Claude 3.5 Sonnet
contextbill model claude-3-5-sonnet-20241022

Pillar 3: Fleet Gateway & Studio

The Fleet Gateway (@switchyardhq/cortexai) is a lightweight, local reverse proxy that runs at 127.0.0.1:52425. It exposes a standard OpenAI-compatible /v1/chat/completions endpoint, allowing any coding agent or CLI to route through Switchyard without modifying application code.

Worktree .env Auto-Provisioning

When an agent worktree is spawned using fleet spawn worker-api --gateway, Switchyard automatically generates an isolated .env.fleet configuration file inside the worktree directory:

ENV · .ENV.FLEET GENERATED IN WORKTREE 
# Auto-generated by Switchyard Fleet Gateway
OPENAI_BASE_URL=http://localhost:52425/v1
OPENAI_API_KEY=fleet-worker-api-token
FLEET_AGENT_NAME=worker-api
FLEET_WORKTREE_PATH=.fleet/agents/worker-api

Agent frameworks automatically discover OPENAI_BASE_URL, routing their completions through the gateway seamlessly.

Tamper-Evident Local Audit Log

Every request processed by the gateway is streamed to upstream providers while being recorded locally in .fleet/audit.jsonl. Each JSON line records:

  • timestamp: ISO 8601 UTC execution time.
  • agent: Name of the originating worktree agent.
  • model: Upstream model identifier (e.g. claude-3-5-sonnet-20241022).
  • prompt_tokens & completion_tokens: Exact token consumption.
  • cost_usd: Calculated monetary cost based on prices.json.
  • duration_ms: Round-trip gateway latency.

Native Desktop Workspace (PyQt5)

For developers who prefer visual interaction, Switchyard includes a native desktop workspace application (cortexai.app) that provides:

  • Visual multi-worktree dashboard with real-time status indicators.
  • Split-screen side-by-side diff viewers for reviewing candidate agent commits.
  • Live token consumption gauges connected to the local gateway stream.

Security & Merge Verification Gates

Switchyard is engineered in compliance with strict pre-launch security principles:

  • Zero Cloud Telemetry (SEC-01 & SEC-02): No source code, diffs, API keys, or transcripts ever leave your workstation.
  • Credential Quarantining: Agent worktrees inherit only the credentials explicitly provisioned in .env.fleet. Host environment credentials remain shielded.
  • Deterministic Merge Gates: Before any branch is merged into the base branch via fleet merge, Switchyard executes a multi-stage verification gate:
    1. Collision Gate: Confirms that the agent branch has zero conflicting touched files with any other concurrent worktree.
    2. Clean Tree Gate: Confirms the agent worktree has zero untracked or unstaged modifications.
    3. Validation Gate: Executes repo-defined test suites and linters. If tests fail, the merge is rejected.
Autonomous Agent Safety Notice

Always review agent diffs before executing fleet merge. Switchyard prevents structural collisions and verifies automated test suites, but human oversight remains essential for validating code intent, architectural consistency, and security boundaries.
