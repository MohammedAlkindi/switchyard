What the data showed

A fifth of the bill was context nobody typed.

Running loadline against a single developer machine with 376 sessions returned the figures below. Every session loads a system prompt, tool catalog, connector definitions and instruction files before doing any work — then re-reads that block on every subsequent turn.

Measured

$22,297 total across 82,767 turns in 376 sessions. Of that, $4,062 is attributable to a median 81,586-token block loaded before any input — 18.2% of spend on that machine.

Interpretation

This is one machine, not a benchmark. The startup figure is a model — prefix tokens priced across observed turns, capped at non-output spend — not a billed line item. Whether it generalizes is untested.

How it works

Four steps, all of them local.

  1. Run npx loadlineNo install, no configuration, no API key.
  2. It reads Claude Code transcripts from diskDefault ~/.claude/projects. Opened read-only; nothing is written back.
  3. Costs are calculated locallyAgainst a dated price table shipped with the package, including per-model and fast-mode rates.
  4. A self-contained HTML report is writtenOne file, no external references. Open it, or send it to someone.

Privacy model

Your transcripts never leave the machine.

No network calls
The shipped build imports only fs, os, path and url. No HTTP client, no socket, no telemetry. A test asserts the generated report contains no external reference.
No external API required
Pricing ships in the package as a dated table. Nothing is fetched at runtime.
Paths redacted by default
Transcript folders are named after the working directory, so the raw label encodes your OS account name and directory tree. That is stripped before rendering; --show-paths is an explicit opt-in.
Zero runtime dependencies
Node built-ins only. No transitive tree to audit.
Report content
Aggregates, session identifiers and token counts. No conversation content is read into the report.
