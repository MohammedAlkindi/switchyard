The number nobody shows you

You pay for the same context on every single turn.

Every session loads a system prompt, a tool catalog, connector definitions and instruction files before it does any work. That block is written to cache once and then re-read on every subsequent turn — so a 500-turn session pays for it 500 times.

It is routinely a double-digit percentage of the bill, and it is the one line item that shrinks by deleting things rather than by working differently. Prune three connectors you never call and the saving lands on every turn of every session, forever.

No per-seat dashboard breaks this out, because from the billing side it is indistinguishable from work. From the transcript side it is obvious.

How it works

Four questions, one command.

01

Where the money goes

Real dollars split across shell, file reads, browser automation, connectors, model output and fixed overhead — priced per model, with fast-mode turns billed at their own rate.

02

The fixed tax

Your median startup prefix, and what you paid to re-read it across every turn of every session.

03

Sessions that produced nothing

Long runs that never wrote a file. Surfaced as a prompt to go look — never as a verdict, because read-only research is real work.

04

Runs that died on startup

A scheduled agent that exits before working looks identical to one that never fired. Transcript size is the only signal that separates them afterwards.

Local by construction

It installs without a security review.

loadline opens no sockets. Not to Anthropic, not to a telemetry endpoint, not to a CDN for a webfont. It reads local files, writes one local HTML file, and exits. There is a test in the suite asserting the rendered report contains no external reference at all, and it is not allowed to fail.

It also ships zero runtime dependencies — Node built-ins only. There is no transitive tree for anyone to audit, and npx stays instant.

That is the whole distribution strategy. Every tool that ships a cloud dashboard has to get through procurement before an engineer can try it. This one gets tried first.

Honest by design

Every assumption is stated, not hidden.

A cost tool that quietly guesses is worse than no cost tool, because you act on it. Where loadline cannot know something, it says so in the report itself:

  • Cache-write TTL is not recorded in transcripts. Writes bill at 1.25× at the 5-minute TTL and 2× at one hour, and the transcript carries a single number with no TTL field. loadline defaults to the cheaper rate — so it understates rather than overstates — names the assumption in the footer, and gives you a flag to see the other figure.
  • Prices carry the date they were compiled. Every report footer cites it. Anthropic first-party rates only; Bedrock and Vertex are partner-priced and deliberately not modelled.
  • Unpriced models are reported, not zeroed. A model with no entry in the table is counted and called out, rather than silently folded into the total as free.
  • Your directory tree is redacted before it reaches the page. Transcript folders are named after the literal working directory, so the raw label encodes your OS account name and your whole path. Since the report is built to be shared, loadline strips that by default and keeps only the project name.
  • “No file written” is a prompt, not a verdict. loadline will not call your session wasteful. It shows you the long ones that wrote nothing and lets you judge — and it tells you that a shell command writing a file does not count toward the flag.
